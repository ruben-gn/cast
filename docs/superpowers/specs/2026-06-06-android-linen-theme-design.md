# Android "Linen Paper" theme — design

**Date:** 2026-06-06
**Status:** implemented
**Scope:** Android app only (webapp restyle is a deliberate later follow-up)

## Problem

The Android app used Material You **dynamic color** (`dynamicLightColorScheme`/`dynamicDarkColorScheme`).
The user's wallpaper is pure black, so the derived palette was near-grayscale with an
essentially random accent (the "green" play button). There was no intentional brand identity.

## Decision

Replace dynamic color with a fixed, deliberate brand theme: **Linen Paper** — a warm,
light, ink-on-paper look with a sienna-red accent. Chosen via an iterative browser
brainstorm (light paper beat teal/amber/indigo/emerald/crimson directions).

### Palette

| Role | Hex |
|------|-----|
| primary / accent | `#D8512A` (sienna) |
| onPrimary | `#FFFFFF` |
| background (page) | `#FBF8F3` (near-white linen) |
| surface (cards/sheets/bars) | `#FFFFFF` |
| onBackground / onSurface (ink) | `#2B241E` |
| onSurfaceVariant (muted) | `#8E8175` |
| surfaceVariant (track) | `#ECE5DB` |
| outline | `#DBD0C0` |
| primaryContainer | `#FBE0D6` |
| onPrimaryContainer | `#4A1A0C` |

### Key choices (confirmed with user)

- **Light + dark, follow system with an in-app override.** Light is "Linen Paper"; dark is a
  warm "Ember" counterpart. `ThemeMode` (`SYSTEM`/`LIGHT`/`DARK`, default `SYSTEM`) is a local
  preference; a Settings segmented control overrides it. (Initially shipped light-only; dark
  was added in a follow-up commit when the user decided they wanted dark after all.)
- **Paper grain on the page background only.** Surfaces stay clean so text contrast is never
  affected. The same grain renders as subtle film grain on the dark page (it adapts to the
  theme background color automatically).
- **Update widget + launcher icon now** so the brand is consistent (they were teal/navy).

### Dark "Ember" palette

| Role | Hex |
|------|-----|
| primary / accent | `#E86A45` (ember — lifted from sienna for contrast on dark) |
| onPrimary | `#3A1B0E` |
| background (page) | `#161210` |
| surface | `#221C18` |
| onBackground / onSurface (ink) | `#F4EAE4` |
| onSurfaceVariant (muted) | `#B3A398` |
| outline | `#5A4F47` |
| primaryContainer / nav indicator | `#6E2C16` |

Dark theme is built with `darkColorScheme(...)` and the same warm surfaceContainer ramp
treatment (warm near-blacks, not Material's cool defaults).

## Components

1. **`ui/theme/Color.kt`** (new) — palette constants, incl. a warm neutral `surfaceContainer*`
   ramp and `outlineVariant`/`tertiary`/inverse roles, so Material3 components
   (`NavigationBar`, elevated surfaces, menus) don't fall back to Material's cool-gray/purple
   defaults and fight the linen.
2. **`ui/theme/Theme.kt`** — static `lightColorScheme` (Linen) + `darkColorScheme` (Ember);
   `CastTheme(darkTheme)` selects between them.
3. **`ui/theme/PaperBackground.kt`** (new) — fills the screen with the linen color and a
   seamlessly-tiled grain overlay (`ShaderBrush` + `ImageShader(TileMode.Repeated)`), hosts
   content on top. Draw alpha `GrainAlpha = 0.55f`.
4. **`res/drawable-nodpi/paper_grain.png`** — 160×160 seamless salt-and-pepper grain,
   generated by `scripts/gen_paper_grain.py` (tile 3×3 → blur → centre-crop so it wraps).
5. **`MainActivity`** — inject `SettingsRepository`, collect `themeMode`, resolve `darkTheme`
   (`SYSTEM` → `isSystemInDarkTheme()`); wrap app in `PaperBackground`; `Scaffold`
   `containerColor = Color.Transparent` so grain shows through; drive system-bar icon
   appearance from the resolved theme (not the device setting) via `WindowCompat` in a
   `SideEffect`, so a forced override still gets the right icon contrast.
6. **`res/values/themes.xml`** + **`res/values-night/themes.xml`** — `windowBackground` =
   linen (light) / ember (night) to avoid launch flash in the common follow-system case.
7. **Theme preference** — `ThemeMode` enum, `Settings.themeMode`, persisted in DataStore via a
   dedicated `SettingsRepository.updateThemeMode` that is **local-only** (never calls the
   server, unlike `updateSettings`). Settings UI uses `SingleChoiceSegmentedButtonRow`.
8. **`res/values/colors.xml`** — `ic_launcher_background` navy `#1A1A2E` → sienna `#D8512A`;
   added `linen_background` + `ember_background`.
9. **Widget** (`NowPlayingWidget.kt` + `drawable/widget_background.xml` +
   `drawable-night/widget_background.xml`) — ink/muted text, accent, and gradient background
   in both light (Linen/sienna) and dark (Ember) via Glance `ColorProvider(day, night)` and a
   `-night` drawable. Follows the **system** dark setting (a widget can't read the app's in-app
   theme override).

## Open / follow-up

- **Grain opacity needs on-device tuning.** `GrainAlpha` (and/or the PNG's baked `MAX_ALPHA`)
  was set on a browser preview; it must be checked on a real phone panel. The user builds on a
  Mac off git, so this is a tuning pass after the first install.
- **Contrast:** white-on-sienna is ~4:1 — fine for the play glyph and large text, marginal for
  very small labels. `onPrimary` is not used for small body text in current screens.
- **Webapp restyle** to match Linen Paper — explicitly deferred.
